1. 影片的架構，用題庫理解

作者以闖關問答為例。本課改用三題虛構的流程常識題：取得題目 → 先作答 → 後端評分 → 留下一筆練習紀錄。分數不是臨床能力認證。

  1. ◫使用者畫面React + Vite顯示題目、收集選項、呈現結果。瀏覽器內的程式可以被查看與修改。
  2. ⇄判斷與驗證Apps Script讀取題目、驗證請求、重新計分、處理重複提交，再寫入紀錄。
  3. ▦資料儲存Google Sheets保存題目與練習紀錄；試算表不分享給一般作答者。

結果沿原路回到畫面：Sheets → Apps Script → React。GitHub Pages 只代管前端成品；Apps Script 在 Google 執行。不需要自己維護伺服器，不代表沒有伺服器或沒有維運責任。

醫護人員虛構耗材領用紀錄領用權限、效期與盤點；多人扣量須處理競爭
EMT／教官AED 教學模擬的步驟與訓練 Log核准固定流程；網路故障時仍能停止與重設

2. 不同起點，不必走同一條路

先保留原生 HTML／CSS／JavaScript 與假資料。完成一正常、一失敗測試後，再來閱讀本頁；不用現在改成 React。

影片路線是 React + 外部 Apps Script API。簡化路線可用 Apps Script HTML Service 顯示頁面，以 google.script.run 呼叫伺服器函式；這不是 GitHub Pages 路線，也不是普通網站都能用的 JavaScript API。兩種路線都要做身分、權限與資料驗證。

不要把目前的 AIedu 教學站轉成 React。下列命令與 workflow 是學員另外建立的 ems-quiz-lab 練習專案使用；本學習站繼續用靜態檔案、main 根目錄發布。

3. 全端架設的操作順序

原影片從需求與工具操作走到發布；本教材補上「後端先驗證、權限先確認、端到端驗收」。每一步都有完成證據，不要一次請 Agent 做完所有階段。

01定義需求與唯一核心流程

先建立 SPEC.md，寫出使用者、輸入、輸出、資料欄位與本次不做。題庫先限定三題、單選、送出與計分；匿名代號只用於對照，不是登入身分。

  • 正常：三題答對顯示 3/3，後端新增一筆紀錄。
  • 失敗：未答完、未知題號、重複題號或不存在的選項，應拒絕而非照常計分。
  • 不做：真實個資、正式考核、AI 自動改醫療答案、公開排名。

完成證據：你能不用 AI，說出成功條件與哪一層檢查。

02準備工具與限定工作區

使用官方 Antigravity、瀏覽器、練習 Google 帳號與 GitHub 帳號。React／Vite 另需 受支援的 Node.js LTS、npm；用 Git 指令才需安裝 Git。本機不必先裝 Python、Docker 或 MySQL。

node --version
npm --version
git --version

目前 Vite 指南列出 Node 20.19+／22.12+ 的相容門檻；能執行不等於仍受安全支援。課程以受支援 LTS 為基準，例如本範本 Node 24，不要求安裝「最新 Current」版。Vite 環境要求／Node 支援週期

建立全新的 ems-quiz-lab 資料夾，只開這個工作區。先確認工具權限、隔離、對外傳輸與審核行為；不啟用 Turbo。Rules 是持續指示，不是作業系統的安全邊界。

03建立 Sheet 的題目與回答欄位

建立私人練習試算表，匯入下載的虛構 CSV 至「題目」工作表。標題與程式約定一致：題號、題目、A、B、C、D、解答。CSV 中解答僅是這三題的示範答案，不是官方醫療答案。

「回答」可用：attempt_id、匿名代號、題庫版本、題號與選項、得分、總題數、提交時間。時間與得分由伺服器產生。若需累積闖關次數、最高分與首次通過，先訂清楚更新規則，再新增欄位。

不要為了串接方便，把試算表設成「知道連結的任何人可編輯」。答案表不應放入前端 public/ 或公開 GitHub。

完成證據：欄位能與 SPEC 對照，試算表未對外開放。

04從 Sheet 建立 Apps Script 後端

在練習 Sheet 選「擴充功能 → Apps Script」。請 Agent 先列後端檔案與 API 契約；你審核後再把程式貼入 Script 編輯器。

  • doGet(e)：健康檢查或回傳題號、題幹、選項，不回傳解答。
  • doPost(e)：接受 attempt_id、代號、題號與選項；驗證後依伺服器答案計分。
  • 回應以 JSON 表達成功或錯誤；前端同時檢查 HTTP 結果、內容型別與 JSON 的 ok，不能只看到 200 就認定成功。
// 只驗證部署連線，尚未讀寫 Sheet；不是完整題庫後端。
function doGet() {
  return ContentService
    .createTextOutput(JSON.stringify({ ok: true, service: 'quiz-lab', version: 1 }))
    .setMimeType(ContentService.MimeType.JSON);
}

不要讓前端傳入「總分 100」就直接寫入。後端還要拒絕非法題號、超長輸入與重複提交；同一 attempt_id 重試不得多記一筆。Sheets 輸入需防範以 = 等字元開頭的內容被解讀為公式。

05測試後端，再部署 Web app

  1. 先在編輯器測試讀取工作表的函式，核對名稱、欄位與空表處理。不要直接執行依賴 e 的 doPost，卻未提供測試事件。
  2. 選「部署 → 新增部署 → 網頁應用程式」，確認「執行身分」及「誰可以存取」。只授予本任務必要的授權。
  3. 組織帳號可能限制外部或匿名存取。以實際選項與管理員規則為準；不繞過安全警告，不為課堂關閉機構限制。
  4. 測試部署的 /dev URL 只供具有編輯權的使用者測試；前端正式連到部署的 /exec URL。
  5. 修改程式後，至「管理部署 → 編輯 → 新版本 → 部署」更新既有部署，或另建部署並更新 URL。只按儲存，未必更新正式服務。

「以我身分執行」不是使用者驗證。請求可能使用部署者的資料存取權；「任何人」更不等於每位呼叫者都值得信任。公開試作僅能是隔離的虛構資料與核准範圍，不能把可寫的正式 Sheet 直接掛上匿名端點。

完成證據：從預計使用的帳號取得健康檢查 JSON，並知道服務使用誰的權限。官方部署說明

06用 Antigravity 建立 React 最小前端

先要求計畫、檔案清單與驗收方式，核准後只建前端。若是新建空專案，可使用官方 React 範本；已有專案請勿覆蓋。套件安裝可能執行安裝腳本，先看來源與影響。

npm create vite@latest ems-quiz-lab -- --template react
cd ems-quiz-lab
npm install
npm run dev

開啟終端機實際顯示的本機網址。第一版先用假資料測試選答案、未答完提示、送出及重新開始，不急著加登入、排行榜或圖片 API。保留 package-lock.json；首次課程後記下 Node 與套件版本，避免每次都重新套用 latest。

完成證據：按鈕可操作，第一次失敗測試正確，檔案確實產生。

07接 API，確認實際讀寫不是假資料

在本機建立 .env.local；公開範本只放佔位值。網址與畫面偏好不是秘密，VITE_ 內容會進入瀏覽器。以下數值為示例，正式通過門檻仍由後端決定。

VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/REPLACE_ME/exec
VITE_QUESTION_COUNT=3
VITE_PASS_THRESHOLD=2

從 import.meta.env.VITE_APPS_SCRIPT_URL 讀取，改環境檔後重新啟動開發伺服器。由瀏覽器 Network 看請求／回應，再到 Apps Script 的執行紀錄與 Sheet 核對相同 attempt_id。

跨來源要實測。Apps Script ContentService 有轉址；某些內容型別或自訂標頭會觸發 CORS 預檢。終端機成功不代表瀏覽器也成功；不能用 mode: 'no-cors' 的 opaque 回應，假裝已讀到 JSON 或寫入成功。也不要依賴 TextOutput 沒有的自訂 CORS 標頭方法。若卡在平台限制，改用具驗證能力的後端／代理，或改採 HTML Service + google.script.run 路線；不要加未知公開 CORS proxy。

JSONP 僅適合非敏感唯讀內容，不作為題庫答案、登入或寫入紀錄的解法。ContentService 轉址與 JSONP

08做一次完整測試與多人測試

先取三題 → 作答 → 後端計分 → 寫入回答表 → 前端顯示。再試空白、未知題號、斷線、重複送出、兩人同時提交，以及直接偽造分數。後端不採信分數，錯誤時畫面應保留可重試資訊，不能顯示完成。

更新最高分、闖關次數或扣庫存是「讀取 → 修改 → 寫入」，可能互相覆蓋。Apps Script Web app 可使用 LockService.getScriptLock()，再以 tryLock／waitLock 取得鎖；逾時要回報，finally 釋放。不要假設 Web app 的 getDocumentLock 一定有值。鎖不等於資料庫交易，也不保護另一個 Script 或人手改表。

完成證據：一筆正常、一筆拒絕、一筆重試不重複，並記錄多人測試結果。正式庫存需求應改用合適資料庫與治理。LockService

10建置與本機預覽

Vite 原始碼不是可直接上傳的成品。依練習儲存庫名稱設定 base；例如 username.github.io/ems-quiz-lab/ 對應 base: '/ems-quiz-lab/'。使用者根網站或正式自訂網域通常是 '/'。

// 新 React 專案 vite.config.js 範例；已有設定請合併，不直接覆蓋。
import { defineConfig } from 'vite';
import react from '@vitejs/plugin-react';

export default defineConfig({
  plugins: [react()],
  base: '/ems-quiz-lab/'
});
npm run build
npm run preview

檢查 dist/、資源路徑與 API URL，測試建置版而非只測 dev。vite preview 用於本機驗收，不是正式後端。第一版單頁不加深層路由；若加 React Router，另處理 Pages 重新整理 404。

11發布新的 React 練習專案

  1. 建立核准的 GitHub 練習儲存庫。免費公開課堂方案可用 Public；公開的是程式與前端，不是試算表。其他可見性／方案另依官方條件。
  2. 本頁下載的 workflow 放入新 React 專案的 .github/workflows/deploy.yml，不要放到 AIedu 教學站；先檢查 Node、lockfile、base 與變數名稱。
  3. 到 Settings → Secrets and variables → Actions → Variables，設定上面三個 VITE_ 值。範本只讀 vars，不存任何秘密。
  4. 到 Settings → Pages → Source 選 GitHub Actions。提交並 push main，確認 Actions 完成安裝、建置、上傳 dist 與部署。
  5. 從部署結果或 Pages 設定取得 HTTPS 網址，用非編輯者帳號與手機驗收。改 Variables 後重新執行工作流；瀏覽器不會自動取得尚未重建的值。

既有 AIedu 是純靜態教學網站，維持「Deploy from a branch → main → / (root)」即可。React 練習專案才需要此建置路線；不要因為學了全端，誤改本網站設定。

GitHub Secrets 只保護工作流中的儲存與使用方式；若把它寫進 VITE_* 或 HTML／JS，建置後仍會公開。真正的 API Key、OAuth token、後端密碼，只放在核准的伺服器設定，不放公開前端。Vite 環境變數

12上線驗收與回復

確認同一筆 attempt_id 可在 Network、後端執行紀錄與回答表對照；重新整理仍看得到需保存的資料。沒有讀寫證據，就不能說完成全端。

前端可回復上一個已驗證 commit 並重新部署；Apps Script 管理部署可改用核准版本；Sheet 需要另外備份與還原演練。三者必須記下版本對照，不能只回復前端就假設資料也回復。

Apps Script 有執行時間、同時執行與每日配額；帳號與服務限制也會變動。不要承諾無限、永久免費或正式營運 SLA。移轉擁有者、組織政策變更與停用帳號也可能影響服務。官方配額

4. 不能照舊說法直接套用的地方

舊說法／易誤解處2026-10-13 教材修正
Antigravity 當時免費、舊 Planning／Fast、黑名單設定核對已安裝產品、方案與權限。工具隔離、指令許可與計畫審核分開確認；黑名單不完整，也不因在容器就保證安全。

GitHub 有檔案，就部署成功看工作流、公開網址、實際 API 與資料寫入；React 需要建置，純靜態教學站不需要換架構。

5. 卡關時，先定位哪一層

現象先看什麼正確下一步
本機 npm 無法執行Node／npm 版本、目前資料夾、package.json確認受支援環境，再看完整錯誤；不亂裝多套執行環境
後端回傳登入 HTML，不是 JSON部署 URL、存取權、執行身分與當前帳號先解決權限；不能 JSON.parse 後硬忽略錯誤
curl 成功，瀏覽器 CORS 失敗OPTIONS、轉址、標頭與 Network核對架構或改合法後端；不關瀏覽器安全
Sheet 沒新增，前端卻說成功後端 ok、執行紀錄、attempt_id拒絕假成功；保留可重試資訊，加入去重
本機正常，上線白畫面base、dist、資源 404、部署 log用實際儲存庫路徑重建；不是重新開放後端權限
兩人同時提交，次數或庫存錯誤讀改寫競爭、鎖與重複請求原子化處理或升級資料庫，不能只加前端按鈕禁用
改 Script，正式頁仍用舊程式部署版本與 /exec URL管理部署更新版本；再核對前後端版本

給 Agent 的除錯資料：出錯層、重現步驟、預期／實際、已去敏的完整錯誤、相關檔案與最後穩定版本。一次只修一個可驗證原因，不要求「把全部重寫」。

6. 你能提出哪些證據？

已勾選 0 / 6。這是自我檢查，不是系統認證。

不對。Secret 一旦被寫入前端建置成品，使用者仍可能查看。關鍵是最後資料流向哪裡，不是欄位名稱叫不叫 Secret。
