1. 課前：先確認是哪個版本

Google 目前分別提供獨立 Antigravity App、Antigravity IDE，以及 CLI／SDK。本教材以獨立 App 為主，附 IDE 對照。請以課程指定的產品與版本操作。Google 入門課

2026-09-22 的 2.17.0 更新把相關設定稱為 Plan Review Policy，並介紹 /plan。舊教材可能仍稱 Artifact Review Policy、Planning／Fast。版本分批推出，請以已安裝介面與對應文件為準，不能假設所有人的按鈕相同。更新紀錄

課堂動作 獨立 App 主路線 IDE 對照
選工作範圍 建立 Project，選練習資料夾 開啟練習資料夾作為 Workspace
提交任務 在該 Project 建立對話 在 Agent 面板提交任務
先規劃 使用 /plan；檢查計畫審核設定 若有 Planning 選項則使用；名稱依版本
找證據 看計畫、變更與成果面板 看 Artifacts 與程式變更
基本方法 需求、計畫、核准、小步測試 相同，不必背相同按鈕位置

安裝與成功條件

  1. 從 Google Antigravity 官方下載頁 選擇課程指定產品及作業系統。不要從第三方下載站取安裝檔。
  2. 準備可使用的 Google 帳號，先完成登入。機構管理帳號的開放條件請先請管理者確認，課堂不臨時繞過限制。
  3. 準備 Chrome 或課程指定瀏覽器。先不串私人雲端硬碟、信箱、院內系統或 MCP。
  4. 建立 emsxai-lab 資料夾，只放假資料與教材。不要把整個桌面或下載資料夾交給 Agent。
  5. 建立 Project 並選該資料夾；在新對話請它「只列出目前專案檔案與路徑，不修改、不執行、不連網」。人工核對範圍。
  6. 完成條件是「能登入、選對專案、看見同一份測試文件」。Python、Node.js、Docker 均依任務需要才安裝。

課前確認可用模型與用量，不保證免費、無限使用或固定額度。若登入或安裝卡住，先共用同組可用電腦，其他人負責規格與測試。

操作速查：Antigravity 快捷鍵與指令｜分清 App、IDE、CLI；含 Mac／Windows 對照與醫療救護練習。

2. 必須先懂的六個觀念

名詞 白話說明 課堂要檢查什麼
Model 提供理解與產生內容的能力 換模型不會取消資安責任
Agent 依任務選擇下一步並使用工具 它打算改什麼、執行什麼
Harness 支撐執行的工具、權限、紀錄與驗收環境 是否可停、可查、可回復
Project／Workspace 本次工作的資料夾範圍 是否誤選其他文件
Context 本次提供的規格、檔案與對話資訊 有沒有提供正確版本與必要條件
Artifact 可查看與評論的工作成果 計畫、程式差異、測試或操作紀錄

Antigravity 是操作 Agent 的開發工具環境，不等於某一個模型。Artifact 可協助檢視成果，但**「AI 說完成」不是實際驗收**。Artifacts 官方說明

3. 一個 Project、一條核心流程

  1. 選對 Project，指向 SPEC.md。
  2. 寫清核心流程和測試。
  3. 用 /plan 檢查計畫，核對權限。

建議專案結構（教學用命名，不是 Antigravity 強制格式）：

emsxai-lab/
  SPEC.md          本次要做什麼、不做什麼
  CLASS_RULES.md   課堂限制，由提示詞明確要求閱讀
  TESTS.md         重現步驟、預期與實際結果
  README.md        如何開啟與重啟
  HANDOFF.md       現況、已知問題、下一步
  data/           虛構測試資料
  output/         index.html、styles.css、app.js

用附件或 @ 檔案選單指向 SPEC.md；介面不同時直接提供專案內相對路徑，並要求 Agent 回報讀到的檔案名稱。不要假設它記得上一段對話。Project 入門

4. 計畫審核與工具權限是兩道關卡

/plan 用來先整理需求與產生可審核計畫。檢查是否有檔案清單、依賴、限制及驗收步驟，再允許進入實作。Plan 官方說明

**課堂教學建議：**計畫採每次審核，不使用自動略過計畫審查。需求模糊、跨檔修改或新增功能都先規劃。若 IDE 有 Fast，僅考慮已明確限定的低風險小修正，仍需測試；不拿「速度快」當作開放權限的理由。Artifact Review

工具權限另行處理檔案、指令與對外操作。官方文件中 macOS／Linux 的 Default 搭配 sandbox，而 Request Review 權限預設並不等於開啟 sandbox。它也與同名的計畫審核選項不同。Windows 與分批更新版本可能有不同邊界。不能只看設定名稱就保證安全。Permissions

本課程先保留隔離與最小範圍，再針對需要的操作確認；不啟用 Turbo 或全域無限制執行。看不懂權限時先停止，請它說明影響，而非一律按允許。

操作情境 學員決定前要問
寫入 output/index.html 是否在本組資料夾？有沒有覆蓋原檔？
下載套件或網站內容 來源何在？是否真的需要？會連到哪裡？
執行終端機指令 目的、工作目錄、讀寫對象及副作用是什麼？
開啟瀏覽器測試 是否只操作本機教學頁？是否涉及真實帳號？
刪除、登入、對外發布 暫停，先核對範圍並取得核准

提示詞、Rules、使用者同意與 sandbox 各有作用，任何一項都不是資料外洩的絕對保證。

5. 用證據除錯

請另一組操作，找出一個問題，修正後重跑舊案例。耗材組不直接說「壞了」，改說「輸入 -2 後，庫存由 10 變 12，但預期應拒絕並維持 10」。

先停止新增功能，只診斷這個問題：
位置：output/index.html 的領用按鈕。
重現：選紗布，輸入 -2，按領用。
預期：顯示錯誤，庫存仍是 10。
實際：庫存變成 12。
請提出最小修正，說明會改哪些檔案，等我確認。
修正後重跑正常領用、負數、空白和超量四個案例。

瀏覽器自動測試或錄影能提供操作證據，但仍要人工用另一支手機和不同輸入試一次。若瀏覽器工具不可用，改人工測試並如實記錄，不因此開放私人帳號或取消全部限制。Artifacts

6. 八個省力習慣

  1. **一次一個任務。**先讓題庫能作答，再選錯題紀錄或搜尋其一。
  2. **指定檔案。**把「改那個」換成檔名、按鈕位置與預期行為。
  3. **先要小計畫。**每階段寫明停下來的條件。
  4. **保留穩定版。**用 Git commit 或另存資料夾；不要假設聊天復原能撤回已發布資料。
  5. **成果要可重現。**除了截圖，也記錄輸入、版本與操作步驟。
  6. **對話過長就交接。**請 AI 更新 HANDOFF.md；新對話明確要求先讀，並核對是否讀到最新版本。
  7. **重複規則寫入文件。**課堂先用 CLASS_RULES.md 明確引用，熟悉後才設定 Rules／Skills。
  8. **限制迭代成本。**不自動升級模型、不重做整頁、不開多代理競賽；遇額度限制就保留檔案轉人工驗收。

7. Rules、Skills 與 Workflows：課後再學

Rules 用來描述持續適用的限制；Skills 用來封裝可重用的工作方法。官方 Rules 支援專案／目錄範圍，設定方式依產品而異。普通 SPEC.md 不會僅因為存在就保證每次自動載入，主課程仍要明確引用。Rules／Skills

IDE 文件另有用斜線名稱呼叫的 Workflows。別把舊 IDE 的檔案路徑、觸發方式或設定直接當成所有版本通用規則。課後要做「發布前檢查」重用流程時，再按實際產品的官方文件建立與驗證。IDE Workflows

CLASS_RULES.md 可寫以下內容（本課程範例，不是程式權限設定）：

所有資料皆為虛構，介面使用繁體中文。
只改 output；不改 data 原始資料。
先說明計畫與驗收方式，確認後才執行。
禁止讀取真實病歷、勤務資料、帳密或院內文件。
下載、登入、外傳、刪除、覆寫與發布前先請求確認。
完成時列出修改檔案、測試證據、限制與未完成事項。

8. 常見卡關與處理

現象 先檢查 本堂處理
找不到教學畫面的按鈕 App 或 IDE？版本是否相同？ 用產品對照表找功能，不硬套舊截圖
找不到 SPEC.md Project 是否指到另一個資料夾？ 先列檔案與路徑，再繼續
已核准計畫，卻還要求權限 計畫與執行是不同關卡 看具體動作、路徑與影響，逐次核對
任務越做越大 提示詞是否含「完整平台」等模糊範圍？ 停止，只保留一條流程
一直顯示成功，實際不能用 是否有真正執行測試？ 要重現步驟，人工重測
權限一直被拒絕 是否越界、連網或安裝新套件？ 不一律允許，請縮小任務
登入／模型／用量不可用 帳號、方案、網路及機構政策 同組共用或人工驗收，不臨時購買
換對話後忘記先前進度 是否有明確交接文件？ 更新 HANDOFF.md 並要求先讀

9. 後續才學 Codex：帶作品與方法過去

下一階段先沿用同一個小作品，不重新做另一套大系統。整理 SPEC.md、README.md、TESTS.md、HANDOFF.md 與可回復版本，讓另一套工具先讀檔、解釋現況，再修一個已知錯誤。

可移轉的是「寫規格、給脈絡、控制權限、看修改差異、測試與回復」；按鈕、設定、帳號與規則自動載入方式需另行學習。此處只定義課程銜接，不提供尚未查核的 Codex 操作步驟。
