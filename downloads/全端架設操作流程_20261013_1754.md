## 先認識三層

React／Vite 顯示題目與收集答案；Apps Script 驗證、計分、讀寫；Sheets 保存題目與紀錄。GitHub Pages 只代管前端。這是輕量原型，不是病歷、正式考核或正式庫存系統。

## 新版 12 步驟

### 01 先寫 SPEC

定義使用者、唯一核心流程、輸入／輸出、欄位與完成條件。題庫只做三題單選、送出、計分。代號不是登入。正常：三題正確得到 3/3 並有後端紀錄；失敗：未答完或非法題號必須拒絕。

### 02 準備工具與工作區

Antigravity、瀏覽器、練習 Google／GitHub 帳號。React 需受支援 Node.js LTS 與 npm；指令版控另需 Git。純靜態主課程不因此多裝 Docker、Python。

```sh
node --version
npm --version
git --version
```

只開新建的 ems-quiz-lab；先確認工具權限、隔離與審核，不啟用 Turbo。Rules 不是系統安全邊界。

### 03 建私人試算表

「題目」欄位：題號、題目、A、B、C、D、解答。可匯入同目錄 quiz-sample_20261013.csv，所有內容均虛構。

「回答」欄位：attempt_id、匿名代號、題庫版本、題號與選項、得分、總題數、提交時間。得分與時間由後端產生。不要公開答案表；禁止直接開放任何人可編輯。

### 04 建 Apps Script

Sheet → 擴充功能 → Apps Script。先審核 API 契約。doGet 回傳題號／題幹／選項，不回傳解答；doPost 驗證並重新計分，再寫入。不要相信前端提交的分數。

先用學習頁的健康檢查範例驗證部署；它還不是完整題庫後端。正式練習另加入欄位驗證、去重、公式注入防護及錯誤回應。

### 05 測試、部署與確認權限

先測試 Sheet 存取函式。部署 → 新增部署 → 網頁應用程式。核對執行身分、允許誰存取、授權範圍與機構政策。以部署者身分執行不等於驗證使用者；公開寫入端點不能拿來處理正式資料。

/dev 供有編輯權者測試；前端使用正式 /exec URL。修改 Script 後需更新部署版本，不是只按儲存。遇授權或安全警告先核對，不照影片直接一路略過。

### 06 建 React 最小前端

以下只用於新空專案，既有專案不可覆蓋：

```sh
npm create vite@latest ems-quiz-lab -- --template react
cd ems-quiz-lab
npm install
npm run dev
```

先以假資料測選答案、未答完、送出及重設，再串接 API。檢查套件安裝影響；保留 package-lock.json，記錄工具版本。

### 07 接上 API

本機 .env.local 可用：

```dotenv
VITE_APPS_SCRIPT_URL=https://script.google.com/macros/s/REPLACE_ME/exec
VITE_QUESTION_COUNT=3
VITE_PASS_THRESHOLD=2
```

VITE_* 會公開到前端；不可放金鑰。這裡的門檻是示例，後端須掌握真正規則。改本機環境檔後重啟 dev；正式站須重建。

由 Network、Apps Script 執行紀錄與 Sheet 的相同 attempt_id 核對。跨來源、預檢與轉址要實測；no-cors 不會讓你讀到 JSON。若受平台限制，改合法後端／代理，或用 Apps Script HTML Service + google.script.run；不能找未知公開 CORS proxy，也不把 JSONP 用於秘密或寫入。

### 08 做完整與多人測試

正常、空白、非法題號、重複提交、斷線、偽造分數與兩人同時送出。attempt_id 重試不可新增兩筆。後端需處理讀改寫競爭；Web app 使用 getScriptLock 並真正取得鎖、逾時回報與 finally 釋放。鎖不是完整資料庫交易，也管不到其他 Script 或人手改表。

### 09 公開前檢查與 Git

gitignore 至少涵蓋 node_modules、dist、.env、.env.*，以 !.env.example 保留無秘密的範本。不要拼成 .nev。已追蹤／曾提交的秘密不會因 gitignore 自動消失；先撤銷、輪替，再處理歷史。

```sh
git status
git diff
git diff --cached
```

逐項加入核准檔案，寫清楚 commit 訊息，再 push。README 寫出用途、欄位、啟動、資料流、限制與回復方式。

### 10 建置並測 dist

Vite 的 base 對應實際儲存庫路徑。例如 username.github.io/ems-quiz-lab/ 使用 /ems-quiz-lab/；使用者根網站或正式自訂網域通常使用 /。

```sh
npm run build
npm run preview
```

檢查建置版、API 參數、資源路徑；preview 不是正式後端。若加深層路由，另處理重新整理 404。

### 11 發布新 React 練習專案

下載 react-pages-workflow_20261013.yml，放到新專案 .github/workflows/deploy.yml。先確認 lockfile、Node 與 base。範本的 VITE_* 由 GitHub Actions Variables 取得；不要塞真正秘密。

Settings → Pages → Source 選 GitHub Actions，提交並 push main，再看每個 job 與部署網址。改 Variables 後重新執行，才會更新建置成品。

重要：目前 AIedu 是純靜態學習站，保留 main 根目錄分支發布，不套用這個 workflow。GitHub Secrets 若被打包進瀏覽器，同樣會外洩。

### 12 上線驗收與回復

非編輯者帳號、手機、重新整理、失敗與重試皆要測；三層能對照實際紀錄。記下前端 commit、Apps Script 部署版本與題庫版本；前端回復不會自動還原 Sheet。建立備份與還原流程。

Apps Script 具配額與執行限制，不能承諾無限／永久免費／正式營運 SLA。正式庫存、考核與病人資料改走機構治理與合適架構。
